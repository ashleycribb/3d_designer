# HVAC 3D Floorplan Engineering Platform: Senior Product Design & Technical Architecture Recommendations

## Executive Summary

As a Senior Product Designer and Principal Engineer inspecting the HVAC 3D Floorplan Engineering Platform, this application demonstrates a strong foundational CAD/BIM architecture. It effectively bridges 2D PDF architectural drawing extraction, 3D parametric WebGL/Three.js rendering, and DDC controls topology mapping.

To elevate this platform from a visualization tool to an industry-standard, high-productivity engineering suite for university facilities and HVAC commissioning teams, we recommend **5 strategic features**. Each recommendation is articulated with a product vision, UX design specifications, technical architecture, and data model changes.

---

## 1. Automated CFM Airflow Balance & Air Distribution Heatmaps

### Product Vision & User Value
- **Problem**: Mechanical engineers currently calculate room-by-room CFM requirements manually or in external spreadsheets, leading to errors in air balance and risk of unconditioned zone spots.
- **User Benefit**: Enables real-time verification of HVAC supply vs. return airflow per room zone. Engineers immediately see if a space is pressurized (positive/negative), under-ventilated, or exceeding CFM thresholds, represented as visual 3D thermal/airflow gradient heatmaps on room floors and drop ceilings.

### UX/UI Design & Workflow
- **Heatmap Layer Toggle**: Add an "Air Balance / CFM Heatmap" visibility mode in the top toolbar.
- **Room Zone Indicators**: Rooms render color-coded floor slabs:
  - 🟩 **Balanced** (Supply within ±5% of design CFM)
  - 🟦 **Positive Pressure** (Excess supply CFM relative to return)
  - 🟥 **Deficit / Under-ventilated** (Insufficient CFM for room volume/occupancy)
- **Interactive Balance Cards**: Clicking a room zone displays a floating summary card showing:
  - Target CFM vs. Sum of Placed Diffusers (`Σ CFM_placed / CFM_required`)
  - Air Changes per Hour (ACH) based on parametric volume (`Length × Width × Ceiling Height`)
  - Auto-distribute button: automatically calculates and snaps diffusers evenly across the ceiling tile grid.

### Technical & System Architecture
- **Frontend (Three.js)**:
  - Create custom `VertexShader` and `FragmentShader` for dynamic planar gradient mapping on Room mesh geometry.
  - Implement a real-time recalculation hook triggered when diffuser positions or flow rates (`airflow_max`) update.
- **Backend (FastAPI & Geometry Service)**:
  - Extend `geometry_service.py` with spatial point-in-polygon queries using `Shapely` to detect which room polygon contains each placed equipment item.
  - Calculate room cubic volume: $V_{\text{room}} = A_{\text{room}} \times H_{\text{ceiling}}$.
  - Calculate required CFM: $\text{CFM}_{\text{req}} = \frac{V_{\text{room}} \times \text{ACH}}{60}$.

## 2. BIM / IFC Export & Bi-Directional Interoperability (openBIM)

### Product Vision & User Value
- **Problem**: Facilities engineers cannot easily export floorplans created or modified in this platform into standard BIM environments like Autodesk Revit, openBIM IFC viewers, or Navisworks.
- **User Benefit**: Bridges the gap between 2D PDF digitization and enterprise facility BIM workflows. Allows engineers to export fully parametric `.ifc` (IFC4 / IFC2x3) models containing walls, rooms, drop ceilings, and HVAC equipment complete with BACnet tags and airflow parameters.

### UX/UI Design & Workflow
- **Export Modal**: Add an "Export BIM (IFC/GLTF)" option in the primary header action menu.
- **Export Options**:
  - Format selection: `IFC4 (Standard BIM)`, `glTF / GLB (3D Web Standard)`, `DXF (2D CAD Lines)`.
  - Layer inclusion checkboxes: Wall geometry, Ceiling Plenums, HVAC Equipment, Control Wire Polylines.
  - Property Set Export: Include BACnet tags, Trane/Carrier model numbers, and CFM parameters in standard `Pset_DistributionFlowElement` property sets.

### Technical & System Architecture
- **Backend Service (`ifc_export_service.py`)**:
  - Integrate `IfcOpenShell` (Python library for IFC processing).
  - Map internal geometry models to IFC schemas:
    - `Wall` $\rightarrow$ `IfcWallStandardCase`
    - `Room` $\rightarrow$ `IfcSpace`
    - `Equipment` (AHU, VAV, Fan) $\rightarrow$ `IfcFlowTerminal` / `IfcEnergyConversionDevice`
    - `ControlAssociation` $\rightarrow$ `IfcRelConnectsElements`
- **Frontend Download Handler**:
  - Stream binaries generated by FastAPI backend directly to the user's browser as attached `.ifc` files.

### Data Schema & Export Mapping

## 3. Multi-Story Vertical Building Stacking & Riser Routing

### Product Vision & User Value
- **Problem**: Complex university campus buildings span multiple stories with shared vertical duct risers, chilled/hot water piping, and mechanical shafts. The current system models single-floor drawings independently.
- **User Benefit**: Enables multi-floor building elevation stacking. Engineers can create multi-story projects, copy floorplan layouts across levels, and visualize vertical duct risers connecting Air Handling Units on upper floors or mechanical penthouses down to VAV boxes on lower levels.

### UX/UI Design & Workflow
- **Floor Navigator Widget**: Left drawer includes a vertical floor selector stack (`Roof / Mechanical Penthouse`, `Level 3`, `Level 2`, `Level 1`, `Basement`).
- **3D Multi-Floor Render**:
  - Exploded view mode: slider expands vertical floor spacing to inspect plenum cavities between levels.
  - Ghosting / Semi-Transparency: Upper and lower floors render in semi-transparent gray to focus on active floor engineering.
- **Riser Connector Tool**: Click-to-connect tool allowing engineers to draw vertical duct shafts (`Duct Riser`, `Pipe Shaft`) through floor slabs between levels.

### Technical & System Architecture
- **Database Schema**: Introduce `Floor` model linked to `Project` (1-to-N). Move `walls`, `rooms`, `drawings`, and `equipment` to reference `floor_id`.
- **Three.js Elevation Matrix**:
  - Group each floor's objects inside a Three.js `Group` object.
  - Transform `Group.position.y` based on cumulative floor heights: $Z_{\text{elevation}} = \sum \text{floor\_heights}$.
  - Implement vertical raycasting across floor groups for riser snapping.

### Data Schema Extensions

```python
# backend/app/models/architecture.py
class Floor(Base):
    __tablename__ = "floors"

    id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
    project_id = Column(String(36), ForeignKey("projects.id", ondelete="CASCADE"), nullable=False)
    name = Column(String(100), nullable=False) # e.g., "Level 1", "Level 2"
    floor_number = Column(Integer, default=1)
    elevation_ft = Column(Float, default=0.0)  # Height relative to ground slab
    height_ft = Column(Float, default=12.0)     # Floor-to-floor height
```

## 4. Interactive DDC Control Engine & Live BACnet / Modbus Simulation Overlay

### Product Vision & User Value
- **Problem**: Controls engineers map control associations statically, but cannot test sequence-of-operations logic (e.g., thermostat setpoint changes triggering VAV damper movement and supply fan speed scaling) prior to field installation.
- **User Benefit**: Transforms the static "Controls View" into an interactive, real-time control logic simulation engine. Engineers can adjust virtual room temperature setpoints, inspect live BACnet object values (AI, AO, BI, BO, AV), and verify DDC control loops visually in 3D.

### UX/UI Design & Workflow
- **Interactive Simulation Bar**: Top control bar with Play / Pause / Fast-Forward controls and speed toggles (1x, 5x, 10x time).
- **Live Signal Overlay in 3D & 2D**:
  - Animated signal pulses move along control wires between devices (e.g., Thermostat $\rightarrow$ VAV Controller $\rightarrow$ Actuator).
  - Status indicators show equipment operational states (Green = Cooling Active, Blue = Heating, Yellow = Damper Adjusting, Red = Alarm).
- **Controls Node Diagram Enhancements**:
  - Double-clicking a node opens a DDC Sequence-of-Operations editor showing live inputs, PID controller outputs, and variable values.

### Technical & System Architecture
- **Backend Logic Engine (`app/services/ddc_simulation_service.py`)**:
  - Simple discrete-event thermal simulation model calculating room temperature drift based on envelope heat gain, occupancy, and supply air temp/CFM.
  - Standard PID loop calculation: $u(t) = K_p e(t) + K_i \int e(t) dt + K_d \frac{de(t)}{dt}$.
- **Real-Time Communication**:
  - FastAPI WebSocket endpoint (`/ws/simulation/{project_id}`) streaming telemetry data at 10Hz to the React frontend.
- **BACnet/IP Integration Support**:
  - Mock BACnet server connector using `BAC0` or `bacpypes3` allowing live polling of actual physical DDC controllers on university networks.

## 5. Automated AI PDF Floorplan Reconstruction Pipeline

### Product Vision & User Value
- **Problem**: While PyMuPDF extracts vector lines, engineers still manually trace or calibrate wall lines for complex architectural floorplans with thousands of raw CAD lines or scanned drawings.
- **User Benefit**: One-click automated floorplan parsing using computer vision and deep vector path analysis to automatically reconstruct clean wall centerlines, detect room boundaries, recognize standard door/window symbols, and identify room number text blocks.

### UX/UI Design & Workflow
- **"Auto-Reconstruct" Action**: Uploading a PDF presents an prominent wizard option: `"Run Automated AI Wall & Room Detection"`.
- **Interactive Review & Clean-Up Workbench**:
  - Displays detected candidate walls overlaid on the original PDF in high-visibility magenta/cyan.
  - Confidence Sliders: Allows engineers to filter low-confidence detected lines (e.g., set threshold to >80% confidence).
  - One-click confirmation converts candidate geometry into parametric editing objects.

### Technical & System Architecture
- **Backend CV Pipeline (`app/services/ai_reconstruction_service.py`)**:
  - **Vector Line Clustering**: Group collinear vector paths extracted by PyMuPDF into structural wall segments using RANSAC or Hough Line Transforms.
  - **OCR Text Detection**: Use `pytesseract` or PyMuPDF text block extraction to locate room numbers (e.g., "RM 101", "LAB 104") and auto-assign them to generated room polygons.
  - **Polygon Closed Loop Finder**: Shapely polygonize algorithms to convert wall centerline networks into closed room polygons automatically.
- **Fallback Raster Pipeline**: OpenCV contour detection for scanned or rasterized architectural PDFs.

## Conclusion & Recommendation Sequence

We recommend implementing these features in **three strategic phases**:

1. **Phase 1 (Immediate UX & Value)**: Implement **Feature 1 (CFM Airflow Balance)** and **Feature 2 (BIM/IFC Export)**. These leverage existing spatial geometry and data models without heavy structural changes.
2. **Phase 2 (Automation)**: Implement **Feature 5 (AI PDF Wall Reconstruction)** to dramatically reduce project onboarding time for engineers uploading raw PDFs.
3. **Phase 3 (Advanced Systems)**: Implement **Feature 3 (Multi-Story Stacking)** and **Feature 4 (Interactive DDC Simulation)** to cement the platform's position as an end-to-end BIM and controls engineering standard.
